# Proposed catalog and conservative editing rules

Pending root review before domain enforcement. No new game-format facts.

1. Load only an explicitly selected local catalog directory, reading one documented catalog.json; no discovery, network or bundled game text. Records use Item/Weapon/Armor/Skill/Decoration/Rampage plus numeric ID and optional equipment kind. Names are locale-keyed. Source/license/edition and declared status/ranges are retained as claims; user JSON cannot establish independent verification or grant write capability. Missing source/license yields UNKNOWN_ITEM; UNSUPPORTED is preserved. A self-declared VERIFIED_ITEM is downgraded to KNOWN_ITEM for effective display and labeled unverified. Catalog limits may be displayed as declared, never used as verified game bounds.
2. Existing money/points operations allow 0 through the original nonnegative value, as a conservative operation envelope, not a game maximum. Missing/negative/unsupported original values are read-only. Staging never increases the original bound. Directory cached-money consistency uses the same primary operation.
3. Item quantity changes and add-known-ID require an originally observed ID. For each ID, sum positive original quantities across all valid records as the conservative total ceiling; use current staged totals for each proposed change, so splitting/adding records cannot bypass it. Any original negative or malformed inventory record makes quantity/add operations read-only until facts resolve it. Zero normalizes an existing record. Delete remains normalization of supported, nonnegative records. Catalog presence or JSON claims cannot expand the same-source ID set or totals. Display the original-total ceiling separately from a catalog-declared max.
4. Existing talisman observed-pair constraint remains unchanged pending reviewed skill/range evidence. Decoration/rampage catalog and known-slot filtering are presentation-only interfaces; no slot writer, character-name writer or new field mapping.
5. GUI explicitly loads catalogs, supports locale names/ID lookup, categories, owned-record filters and sorting, with numeric targets unchanged. Unknown IDs cannot be newly added. Existing raw research primitives remain a separate experimental API and are not promoted as range-validated game editing.
6. Earlier increased-value R5/R6 exports remain historical evidence from the prior policy. Do not rewrite actual EXPORTED manifests or game-validation status. Add fresh focused tests for new policy; preserve prior reports.

Review outcome: approved by root with normal raw GUI made read-only, no catalog claims authorizing writes, and presentation-only 1..4 slot filtering. See audit research-r7/spec-review.json for original proposal hash and decision; implementation follows these clarifications.
