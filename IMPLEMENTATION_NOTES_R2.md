# Revision 2 implementation notes — experimental review candidate

Author credit: 花木错. Written with GPT assistance using the reviewed facts in `clean_spec/r2`, the prior admitted packet and this new foundation. This is not release licensing documentation. Historical revision-1 decisions and validation remain in `IMPLEMENTATION_NOTES.md`; this document supersedes the former opaque-only structural scope.

## Implemented scope

`Document.Inspect` now requires a matching final little-endian MurmurHash3 x86_32 checksum with unsigned seed 4294967295 before header/payload interpretation, decompression or structural allocations. It reports CHECKSUM_MATCHED. Integrity, game identity and game semantics remain UNVERIFIED: this noncryptographic check is neither authenticity nor proof that the file is a valid game save.

Compressed inputs validate the additional wrapper relations, total-length alignment and zero poststream padding. Structure is fully traversed from coordinate 12 in either the original uncompressed coordinate system or the first 12 header bytes plus decoded payload. Decoded bytes are now retained privately, unlike revision 1. A flat immutable event collection preserves sequence, duplicate identifiers, class identifiers, widths, counts, modes and whether a tag was implied. Original source bytes, payload bytes and nonzero alignment bytes are retained without normalization. All exposed byte copies are defensive clones. No scalar number interpretation or game text role is provided.

Root bodies and mode-1 array bodies create implied tag-17 events without consuming an on-disk tag. Root depth is zero. Object fields and array elements each increment depth. This is the reviewed measurement convention, not extra grammar bytes.

Array admission follows the later reviewed prefix refinement: mode 1 only 17/8; mode 0 only the enumerated prefix list. The 15/32 prefix still has variable-length UTF-16 elements. Empty 4/1 arrays are preserved but nonempty ones fail closed. Other unobserved array forms, primitive tags/widths, modes, overflows and policy excesses fail. Strict UTF-16 decoding validates byte sequences without returning raw strings to CLI.

The CLI displays READ_ONLY, CHECKSUM_MATCHED, EXPERIMENTAL, root/value counts, maximum depth, consumed virtual coordinate, nonzero padding count, array count and text-value count. It does not display structural player strings or fields. Empty structural sequences are representable but do not establish a game identity. Twelve zero structural bytes are also a valid grammar instance containing one empty root object; they cannot be treated as malformed merely because they look uninformative.

Existing `CopySession` and `SafeFiles` implementation is unchanged. Selection now uses the stricter checksum/structure admission before export. New destinations, backup identity, digest verification, source-change detection and documented bounded Windows path protections remain. Single- and multi-field edits are still UNSUPPORTED. No modified document serializer or game-write API was added. `SyntheticR2` constructs fresh test bytes only and does not accept a document or save to modify.

## Validation actually executed

Final run: 108 top-level R2 cases passed, including one aggregate invoking 20 retained copy-safety cases, all passing. Thus there are 107 direct R2 test cases plus 20 retained copy cases; the aggregate is not an additional independent assertion family. Results and actual source hashes are in `test-results-r2.json`; retained copy details are in `test-results-copy-r2.json`. The former `test-results.json` remains the historical 44-case R1 result and was not overwritten.

Coverage includes all 21 independent checksum vectors, every admitted scalar tag/width combination, every admitted array prefix including empty-only tag 4, both array modes, nested objects, UTF-16, duplicates and ordering, explicit golden non-modulo alignment coordinates for widths 12 and 116, nonzero padding, all shortened synthetic compressed regions with independently corrected wrapper bounds, extra unused compressed bytes, envelope relations, mismatch precedence and exact unchanged round trips.

Policies are exercised at and beyond their actual boundaries: 10,000/10,001 object fields, 500,000/500,001 array elements, 100,000/100,001 UTF-16 units, depths 128/129 and 2,000,000/2,000,001 value events. A source of exactly 64 MiB passes the source bound and reaches a structural rejection; 64 MiB+1 fails the source bound. Exactly 64 MiB decoded data reaches structural validation, and decoded expansion to 64 MiB+1 with a declared 64 MiB limit fails during decompression. These exact-size fixtures intentionally have unsupported structure; they demonstrate bound placement, not acceptance as game saves.

The initial R2 run had one failure among 106 new cases: a test incorrectly expected twelve zero bytes to be malformed, although they form one empty root object. The fixture was corrected to an over-limit object count; the grammar was not changed to satisfy the mistaken expectation. Two more actual byte-limit cases were then added. Final execution passed 108/108 plus 20/20 retained copy cases. The Release build succeeded without warnings/errors.

No original saves or audit-side probes were read by this implementer. The reviewer separately owns real-sample testing. The admitted observation sets contain eight instances but only five unique input hashes, not eight independent samples. Measured grammar fit and checksum relationships do not establish universal format correctness, independent historical discovery or game editing support. Existing path-race, crash-recovery and procedural-isolation limitations remain.
