# Source and preservation policy

This policy records the public-preview and preservation scope. The maintainer explicitly authorized offline name/template-add/whole-Build implementation and reviewed GitHub synchronization on 2026-10-12, superseding the earlier software-development pause for that scope. The NS device is still on loan and native-device validation remains unavailable. This authorization does not extend to game operations, original-save modification or uploads of private inputs.

1. Preserve originals, private user files and all existing local Git history. This proposed allowlisted snapshot does not authorize a history rewrite, old-history push or new repository initialization.
2. Retain truthful origin statements: GPT assistance, reviewed fact-packet implementation, measurement-role REE hypothesis exposure and shared-machine procedural isolation limits. Do not make all-original, strict clean-room, absolute no-similarity or legal-clearance claims.
3. Record exact source, commit/version, license, attribution, scope and modifications before importing outside code/data/assets. Attribution and renaming do not establish permission to reuse protected expression.
4. Keep licensed third-party material under its distinct notice. A proposed own-code MIT grant covers only rights the publisher may grant; it does not relicense game content or settle early authorship gaps.
5. Exclude catalogs/raw game data, saves, exports/backups, private reports, screenshots, keys, reference archives, build caches, PDBs, binaries and unreviewed history from this public preview.
6. Keep synthetic software results separate from byte observations, user reports and complete native game-validation evidence. Do not invent history or relabel an older result as a fresh test.
7. Keep offline application work, real save/device activity, external contact, reviewed source synchronization and deployment within their separately authorized scopes. R11 implements from the three reviewed packets and the independent public app only; it does not import old editor code, private probes, save artifacts, game catalogs or archives. Root review owns private regression and the final public manifest/source synchronization.

The original project's private review policies and the implementation isolation record remain at their original locations. ISOLATION_LOG.md retains the public procedural record; its local commit-email strings are omitted in this public copy, with originals unchanged.
